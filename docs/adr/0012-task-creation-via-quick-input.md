# 0012. Создание задачи через быстрый ввод заголовка

### Дата
2026-10-25

### Статус
Принято

### Контекст
Задачу нужно создавать быстро, в одно движение, при этом у неё есть множество необязательных полей
— проект, дедлайн, теги, подзадачи, повторение. Если открывать полноценную форму сразу, быстрый
ввод теряется. Если создавать пустую задачу заранее, в базе копятся записи без заголовка от тех,
кто передумал.

### Решение
FAB открывает быстрый ввод одного поля — заголовка. Задача вставляется в базу только тогда, когда
заголовок непустой, после чего открывается TaskDetail для дозаполнения остального. Пустой заголовок
невалиден по определению, валидация живёт в одном месте, а не на каждом экране.

### Последствия
Создание задачи — два касания и ввод текста. В базе не появляется записей-призраков: отмена ввода
не оставляет следов, и синхронизации нечего отправлять. Инварианты модели сохраняются, задача без
заголовка невозможна в принципе. Пользователь, которому нужно сразу задать дедлайн, проходит через
два экрана вместо одного.

### Рассмотренные альтернативы
Полная форма по FAB — быстрый ввод теряется, а большинство задач создаётся без дополнительных
полей. Создание пустой задачи с переходом в TaskDetail — проще в коде, но требует чистки
незаполненных записей и допускает задачу без заголовка в модели.
