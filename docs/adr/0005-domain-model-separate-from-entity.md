# 0005. Доменная модель отдельно от Room-сущностей

### Дата
2026-09-08

### Статус
Принято

### Контекст
Room-сущность и доменная модель задачи различаются. В сущности есть служебные поля синхронизации
(isDirty, serverVersion), денормализованный nextOccurrenceAt и сериализованное в JSON правило
повторений. Доменному слою и UI ничего из этого не нужно. Обратно — доменная модель хранит статус
sealed-иерархией и повторения типизированными классами, чего SQLite не умеет.

### Решение
Два набора типов и мапперы между ними. Entity живёт в :core:database, доменная модель —
в :core:domain, мапперы — в :core:data. Репозиторий принимает и отдаёт только доменные типы.
:core:domain не зависит от Room и ничего не знает о базе.

### Последствия
Доменный слой тестируется без базы и без Android. Служебные поля не протекают в UI, из-за чего
невозможно случайно показать или отредактировать их с экрана. Изменение схемы базы не ломает
доменную модель, и наоборот. Цена — мапперы нужно писать и поддерживать руками, при добавлении
поля правок в двух местах.

### Рассмотренные альтернативы
Одна модель с аннотациями Room — меньше кода, но Room протекает в domain и UI, sealed-статус
не выражается, а доменные тесты требуют инструментальных.
