# 0003. Хранение повторений в виде json

### Дата
2026-09-05

### Статус
Принято

### Контекст
У задач могут быть повторения (каждый день, раз в неделю, по вторникам и четвергам, каждый второй
понедельник месяца и т.д.). Правила повторений имеют разную форму для разных типов. В SQLite отсутствует
возможность хранить повторения напрямую с указанием периодичности. Нужен универсальный способ хранения
повторений, который не потребует большого количества миграций базы данных при изменении структуры.

### Решение
Поле recurrence: String? хранить в виде строки с json и полями повторений по правилам RRULE. Например:
{ "v": 1, "freq": "DAILY", "interval": 1 }. "v" - версия, нужна для выявления обновления в формате записи
повторений, "freq" - тип повторений, "interval" - интервал повторений. nextOccurrenceAt: Long? — 
денормализованная дата следующего вхождения, epoch millis, индексируется. Существует ради запроса 
"какие задачи должны породить экземпляр" — по JSON такой запрос невозможен. В доменной части nextOccurrenceAt
отсутствует, нужна только для Entity в database модуле и для записи в базе данных. Вычисляется в маппере
в момент сохранения задачи, вместе с сериализацией правила. Точка отсчета берется из поля
dueDate задачи.

### Последствия
Новая версия формата записи никак не влияет на базу данных. Поле не может разъехаться с правилом,
потому что записывается только вместе с ним. Правило непрозрачно для SQL. Нельзя отфильтровать 
или отсортировать по содержимому JSON. У повторяющейся задачи dueDate обязателен.

### Рассмотренные альтернативы
Полноценный RRULE как строка стандарта (полноценная реализация стандарта сейчас избыточна, но именование
заимствовано, чтобы переход не потребовал переделки модели.).
