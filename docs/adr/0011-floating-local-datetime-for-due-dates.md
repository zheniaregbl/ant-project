# 0011. Floating local date-time для дедлайнов

### Дата
2026-09-26

### Статус
Принято

### Контекст
У задачи есть дедлайн, у повторений — дата окончания. Если хранить их как абсолютные метки,
при смене часового пояса «завтра в 9:00» превратится в другое время. Пользователь, перелетев
в другой пояс, ожидает, что утренняя задача останется утренней. Отдельно: у части задач время
суток значимо (встреча в 15:00), у части нет (сделать до пятницы).

### Решение
Дедлайны и даты окончания повторений хранятся как floating local date-time, без часового пояса.
Рядом — булев флаг, означающий, что время суток значимо; при false задача считается привязанной
только к дате. Служебные метки времени (updatedAt, completedAt) остаются абсолютными. Типы:
kotlin.time.Instant для абсолютных меток, kotlinx.datetime.DayOfWeek для дней недели в правилах
повторений.

### Последствия
Дедлайн не съезжает при смене пояса и переходе на летнее время. UI знает, показывать ли время
рядом с датой, и не пишет «до пятницы, 00:00». Сортировка задач с незначимым временем внутри дня
требует отдельного решения, порядок между ними не определён. Напоминания придётся переводить
в абсолютное время в момент планирования, в текущем поясе устройства. Сравнение дедлайна
с «сейчас» требует явного указания пояса и не делается прямым сравнением чисел.

### Рассмотренные альтернативы
Абсолютные метки для всего — единообразно, но дедлайны съезжают при смене пояса. Хранение пояса
вместе с датой — усложняет модель ради сценария, которого в личном планировщике практически нет.
